# Implementation Boundaries

This document exists to prevent portfolio language from drifting beyond the evidence.

## Verified within recorded environments

Historical project records include implementation/test evidence for multiple NOEMA/NOMI package, OS-foundation, GUI, integration, discovery, and sandbox milestones.

The public portfolio therefore claims **recorded implementation/test evidence**, not universal production readiness.

## Implemented but not fully proven in final target environment

Examples across the project history include:

- desktop/Tauri-oriented source work
- browser and mock-bridge behavior
- integration-gate logic
- dashboard/browser surfaces
- forecast/extent/scheduler candidates

These are not represented as final native production deployment.

## Prototype / simulation

Examples include:

- browser interface prototypes
- simulated hardware paths
- analytical simulations
- mock/offline provider paths where explicitly labeled

Prototype evidence is still useful engineering evidence, but it is labeled as prototype evidence.

## Planned / research

Examples include areas such as:

- final OS distribution choices
- production signing hierarchy
- final hardware-backed privileged environment
- final storage/network topology
- final voice/model selections
- broader physical embodiment work

These remain architecture/research directions rather than shipped claims.

## Rule for public claims

A recruiter-facing statement should fall into one of four forms:

- **Built and tested:** implementation + relevant validation evidence exists.
- **Implemented:** code exists, but final environment validation is incomplete.
- **Prototyped:** behavior/interface was intentionally simulated or modeled.
- **Designed / researched:** architecture exists without an implementation claim.

When uncertain, use the weaker accurate statement.

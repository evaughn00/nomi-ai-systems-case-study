# Interface & Systems Design

## Design thesis

NOMI's interface is designed as a **governance and observability surface**, not just a chat window.

The user should be able to see what the system believes it is doing, what authority is active, what is simulated, and where evidence came from.

## Validated browser prototype

Recorded validation for one phone-first/browser prototype reported:

| Measure | Count |
|---|---:|
| Connected routes | 13 |

The validation also recorded a clean browser console and no inert buttons.

## Governance visibility

The design system calls for visible distinction among:

- runtime state
- simulation vs. execution
- approval status
- current user / authority
- permissions
- provenance
- safety restrictions
- blocked gates
- connection state
- recovery status

## Adaptive semantic theming

The interface design explored adaptive changes to visual atmosphere while preserving stable navigation and safety cues.

The principle is:

> Meaning may change the presentation, but it should not erase orientation, accessibility, or control.

## Interaction work

Prototype work included:

- desktop pointer flyovers
- touch long-press equivalents
- local ambient audio
- explicit sound activation
- voice selection/read-aloud hooks
- haptic integration
- responsive phone/desktop behavior
- visible feedback/toasts
- reduced-motion support

## Why this matters for AI systems

An AI system can be technically safe while still being operationally confusing. Interface design is part of safety when it communicates:

- whether a result is observed or inferred
- whether an action is real or simulated
- whether a change is pending or approved
- whether a capability is available or blocked

That makes product design and governance architecture part of the same engineering problem.
